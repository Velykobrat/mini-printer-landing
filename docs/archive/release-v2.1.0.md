- `.gitattributes` і нормалізація CRLF усувають хибний price/schema/CSP drift на Windows.

## Діагностика мобільної sticky-панелі

Збій попереднього браузерного сценарію був помилковим очікуванням тесту. `scrollIntoViewIfNeeded(#features)` центрує секцію залежно від її розміру та viewport і не гарантує, що Hero CTA вже пройшла поріг показу панелі.

Відтворення після переходу desktop → mobile, viewport висотою 844 px:

| Ширина | Нижній край Hero CTA | Стан панелі | Пояснення |
| --- | --- | --- | --- |
| 375 px | −26.77 px | Видима | CTA пройшла буфер −16 px |
| 390 px | −14.42 px | Прихована | CTA ще всередині буфера −16 px |

Після явного прокручування нижнього краю CTA приблизно до −32 px панель правильно з’являється на обох ширинах. IntersectionObserver відстежує Hero CTA й order, а passive scroll/resize події запускають перевірку геометрії через requestAnimationFrame. Показ відкладається на 180 мс, приховування негайне. Order приховує панель за 128 px до входження у viewport; фокус у полях, значне зменшення visual/layout viewport та zoom також її пригнічують. CSS показує панель тільки до 680 px, залишаючи резерв унизу сторінки, коли панель видима.

У production JS/CSS панелі змін не внесено. Оновлений браузерний тест перевіряє реальну геометрію CTA та віддаленість order перед очікуванням показу й чекає зміни стану, а не лише 250 мс після прокручування довільної секції. Регресійний node:test фіксує обидва відтворені положення та повернення до Hero. MutationObserver у QA перевіряє один стабільний показ без повторного перемикання у контрольованому інтервалі.

## Межі QA

Локальні перевірки не підтверджують production WAF/env/CSP headers, GA4 Enhanced Measurement/destinations/DebugView або доставку через реальний Telegram. Не виконано незалежний screen-reader аудит, Safari/iOS/Android та фізичну мобільну клавіатуру. Фактичні умови доставки, оплати, гарантії й комплекту підтверджує власник; pending-поля не публікуються як факти.

## Відтворення браузерного QA

Запустіть `npm run dev`, потім `npm run qa:browser` у середовищі з Playwright і Chromium. Якщо пакет не резолвиться стандартно, задайте `PLAYWRIGHT_MODULE` абсолютним шляхом до `playwright/index.mjs`, а `BROWSER_EXECUTABLE` — до Chrome. `QA_BASE_URL` підтримує тільки localhost/loopback. Playwright не додано до обов’язкових npm-залежностей; `npm test` і `npm run check` залишаються самодостатніми.
